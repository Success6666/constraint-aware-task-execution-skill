## 目标与测试边界

将支付重试服务按真实依赖进行集成测试：不使用 mock；使用支付渠道的 sandbox、测试数据库、消息队列和可配置的测试支付网关。测试网关只返回预先定义的真实 HTTP 响应和延迟，用于控制场景，不替换被测重试逻辑。

## 核心设计

### 1. 支付状态机

明确并持久化以下状态：

- `PENDING`：待支付
- `PROCESSING`：请求已发出或处理中
- `SUCCEEDED`：成功，终态
- `RETRYING`：等待下次重试
- `FAILED`：永久失败，终态

每笔支付至少保存：`payment_id`、业务订单号、幂等键、尝试次数、下次重试时间、最后错误码、渠道交易号、状态更新时间。

状态迁移只能由合法事件触发；`SUCCEEDED` 和 `FAILED` 不允许再次进入重试。

### 2. 重试策略

配置化以下参数：

- 最大尝试次数，例如 5 次
- 基础退避时间，例如 1 秒
- 指数退避：`delay = min(base * 2^(attempt-1), max_delay)`
- 随机抖动，避免批量重试同时发生
- 总超时时间和单次请求超时时间
- 明确的可重试错误分类

建议：网络超时、连接失败、HTTP 408、429、5xx 属于瞬时失败；余额不足、卡号无效、风控拒绝、订单已关闭等业务错误属于永久失败。错误分类必须由渠道错误码和 HTTP 状态共同决定，不能仅按 HTTP 5xx 判断。

## 测试环境

1. 启动真实支付服务、测试数据库、消息队列和定时任务。
2. 使用 sandbox 渠道或可编程测试支付网关。
3. 测试网关支持按支付单号配置：成功、超时、连接断开、429、500、余额不足等结果，并记录实际收到的请求次数、请求体和幂等键。
4. 使用可推进的测试时钟或将退避调至毫秒级；不通过替换函数返回值来控制时间。
5. 每个测试使用独立订单和幂等键，测试结束清理数据。

## 测试用例

### A. 成功

- 首次请求成功：状态变为 `SUCCEEDED`，只产生一次渠道扣款，记录渠道交易号。
- 成功响应重复到达：支付仍只有一个成功结果，不重复发起扣款。
- 渠道返回成功但本地提交前进程重启：恢复任务后查询或重试不会造成重复支付，最终状态正确。

### B. 瞬时失败

分别验证：连接失败、请求超时、HTTP 408、429、500、502、503。

断言：

- 状态进入 `RETRYING`，尝试次数递增。
- `next_retry_at` 符合退避公式和最大上限。
- 到达重试时间前不会再次调用渠道。
- 到达时间后重新执行，并最终在渠道恢复时变为 `SUCCEEDED`。
- 达到最大尝试次数后变为 `FAILED` 或进入人工处理状态，不能无限重试。
- 每次重试都带相同的业务幂等键，并带唯一的请求追踪标识。

### C. 永久失败

验证余额不足、卡号无效、支付方式失效、风控拒绝、订单关闭等错误。

断言：

- 第一次收到永久错误后立即进入 `FAILED`。
- 不创建下一次重试任务。
- 不因定时扫描、消息重复投递或服务重启而再次扣款。
- 对外返回稳定的业务错误码和可展示的失败原因。

### D. 退避

使用测试时钟验证时间序列，例如基础时间为 1 秒、上限为 8 秒时，重试时间应近似为 1、2、4、8 秒；抖动应始终落在规定范围内。

同时验证：

- 退避时间不会超过最大值。
- 服务重启后仍依据持久化的 `next_retry_at` 执行。
- 多个失败支付不会在同一时刻集中重试。
- 修改配置只影响新任务，已有任务的策略按产品约定处理并有明确测试。

### E. 幂等性

覆盖以下重复场景：

1. 同一幂等键并发提交两次：只产生一次渠道扣款。
2. 同一请求因客户端重试再次到达：返回第一次支付结果。
3. 消息重复投递：只处理一次有效状态迁移。
4. worker 崩溃后任务重新领取：不会重复扣款。
5. 渠道响应超时但实际已扣款：重试前先按幂等键查询渠道结果；若渠道不支持查询，则必须依赖渠道幂等键保证安全。
6. 同一业务订单使用不同幂等键：按业务规则拒绝，或明确允许创建新支付，不能产生未定义行为。

数据库至少建立：

- 幂等键唯一索引
- 业务订单号唯一约束（若订单只允许一次支付）
- 状态和版本号，用于乐观并发控制
- 重试任务的唯一约束，避免重复创建任务

## 验证方式

每个用例同时检查四类结果：

1. **业务结果**：支付最终状态、错误码、渠道交易号。
2. **副作用**：渠道实际扣款次数、消息数、重试任务数。
3. **时间行为**：尝试间隔、截止时间、最大尝试次数。
4. **一致性**：数据库状态、渠道查询结果、重复请求返回值一致。

## 验收标准

- 所有成功场景最终只产生一次扣款。
- 所有瞬时错误按策略重试，并在恢复后成功或达到上限后明确失败。
- 所有永久错误不重试。
- 重试任务可跨进程重启恢复，且不会重复执行支付。
- 任意重复请求、重复消息和超时恢复场景都满足幂等性。
- 测试报告包含每次渠道调用、幂等键、尝试次数、退避时间和最终状态，能够据此定位失败原因。
