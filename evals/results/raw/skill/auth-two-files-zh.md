修复方案限定在两个文件内：

- `src/auth.ts`：实现过期检测、刷新并发控制和统一错误处理。
- `tests/auth.test.ts`：补充并发、错误响应及回归测试。

**`src/auth.ts` 方案**

1. **统一判断令牌过期**
   - 对响应状态 `401` 进行处理。
   - 如果响应体包含明确的过期错误码（例如 `token_expired`），也视为过期。
   - 其他 `4xx/5xx` 不触发刷新，直接转换为现有错误类型或保留响应信息。

2. **刷新请求 single-flight**
   - 增加模块级或实例级 `refreshPromise`。
   - 第一个请求发现令牌过期时发起刷新；后续并发请求复用同一个 Promise。
   - 刷新成功后更新 access token，并让所有等待中的请求使用新令牌重试。
   - 刷新完成后将 `refreshPromise` 清空，确保下一次过期可以重新刷新。
   - 刷新失败时所有等待请求收到同一个失败结果，避免重复刷新和状态不一致。

   示例逻辑：

   ```ts
   let refreshPromise: Promise<string> | null = null;

   function refreshOnce(): Promise<string> {
     if (!refreshPromise) {
       refreshPromise = refreshAccessToken()
         .then((token) => {
           setAccessToken(token);
           return token;
         })
         .finally(() => {
           refreshPromise = null;
         });
     }

     return refreshPromise;
   }
   ```

3. **限制重试**
   - 每个原始请求最多因令牌过期重试一次。
   - 使用内部参数或请求上下文标记 `hasRetried`，避免刷新后仍返回 `401` 时无限循环。
   - 重试时重新构造请求头，确保使用最新 access token，而不是复用旧 header。

4. **错误响应处理**
   - 原始请求收到 `401` 后，先尝试单次刷新。
   - 刷新 token 无效、过期或接口返回 `401/400` 时：
     - 清除本地 access token；
     - 保留或清理 refresh token，按现有认证状态约定处理；
     - 抛出可判定的认证错误，例如 `AUTH_EXPIRED`。
   - 网络错误、解析错误和服务端 `5xx` 不应被伪装成 token 过期错误，应原样传播或映射为已有网络错误。
   - 刷新失败时不要重试原请求，避免产生额外请求和误导性错误。

5. **响应体解析**
   - 对 JSON 错误响应和非 JSON 响应分别处理。
   - 错误对象至少保留 `status`、服务端 `code` 和 `message`，方便调用方和测试断言。
   - 不假设所有 `401` 都是过期；若项目已有服务端错误码，应优先按错误码区分。

**`tests/auth.test.ts` 回归测试**

至少增加以下场景：

1. **单请求过期后刷新并重试**
   - 首次业务请求返回 `401 token_expired`。
   - 刷新接口成功返回新 token。
   - 原请求使用新 token 重试并成功。
   - 断言业务接口调用两次、刷新接口调用一次。

2. **并发请求只刷新一次**
   - 同时发起多个使用旧 token 的请求。
   - 所有请求首次返回过期响应。
   - 断言刷新接口只调用一次。
   - 断言所有原请求最终成功，并且重试请求都携带新 token。

3. **刷新失败时的统一结果**
   - 刷新接口返回 `401` 或表示 refresh token 无效的 `400`。
   - 并发请求全部失败，且错误类型/错误码一致。
   - 断言不会再次重试原请求。
   - 断言 access token 已清理。

4. **重试次数限制**
   - 刷新成功但重试后的业务请求仍返回 `401`。
   - 断言只发生一次刷新和一次重试，最终返回认证错误，不进入循环。

5. **非过期错误不刷新**
   - 业务请求返回 `403`、普通 `400` 或 `500`。
   - 断言刷新接口未调用。
   - 断言错误中的 HTTP 状态和服务端错误码被保留。

6. **网络与非 JSON 错误**
   - 刷新接口网络失败。
   - 业务接口返回非 JSON 的 `401`。
   - 断言错误能够稳定抛出，不因解析失败掩盖真实原因。

7. **刷新状态可恢复**
   - 第一次刷新失败后，下一次独立请求仍可重新触发刷新。
   - 用例结束后验证 `refreshPromise` 已解除占用，避免后续请求永久复用已拒绝的 Promise。

测试中的请求 mock 应明确记录调用顺序、请求头和调用次数，这样可以同时验证并发合并、重试使用新 token 以及错误传播行为。
