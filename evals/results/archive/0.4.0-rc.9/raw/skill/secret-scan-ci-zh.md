## 密钥检测与例外审批流程

### 1. 密钥分类与策略

将扫描结果分为：

- **真实凭据**：云访问密钥、数据库密码、JWT 私钥、OAuth 密钥、生产令牌等。
- **疑似凭据**：高熵字符串、符合密钥格式但尚未确认用途的内容。
- **测试凭据**：明确为不可用的固定值，例如 `test-token-not-valid`。
- **允许例外**：经审批、范围明确且有过期时间的误报或历史样例。

策略要求：

1. 任何未经批准的真实凭据都必须阻断合并和发布。
2. 凭据不得写入源代码、配置文件、镜像层、构建产物或日志。
3. 例外只能针对特定检测结果，不得以目录或文件整体跳过扫描。
4. 例外必须包含负责人、理由、风险评估、审批记录和到期时间。

### 2. 本地检查

开发者提交前执行：

```bash
secret-scan --staged
```

建议配置 pre-commit hook，对暂存区执行扫描，并启用：

- 常见云厂商和第三方服务规则；
- 自定义组织密钥前缀、内部域名和令牌格式；
- 熵检测；
- 历史提交扫描（定期执行，不必每次提交都扫描全部历史）。

发现结果后：

1. 立即从代码和暂存区删除；
2. 判断是否已被使用或暴露；
3. 若是真实凭据，按轮换流程处理；
4. 若为误报，提交例外申请，而不是直接添加忽略规则。

本地扫描失败时不应允许提交，除非开发者明确使用经过审批的例外标识。

### 3. CI 流程

在以下阶段执行扫描：

- Pull Request：扫描变更文件和提交差异；
- 主分支：扫描完整仓库和 Git 历史；
- 发布构建：扫描源码、依赖打包内容、容器镜像和生成产物；
- 定期任务：至少每日扫描默认分支及重要制品。

推荐流水线：

```text
检出代码
  -> 密钥扫描
  -> 解析例外清单
  -> 验证例外审批和有效期
  -> 发现结果分类
  -> 运行测试与构建
  -> 发布
```

CI 判定规则：

| 结果 | CI 行为 |
|---|---|
| 未发现密钥 | 通过 |
| 已批准且未过期的误报 | 通过，并产生审计日志 |
| 疑似凭据，待人工确认 | 阻断合并，进入安全审查 |
| 未批准的真实凭据 | 必须失败，禁止合并和发布 |
| 例外已过期或审批无效 | 失败 |
| 扫描器不可用、规则加载失败 | 失败，不得静默跳过 |

CI 中不得允许通过环境变量关闭扫描，也不得接受类似 `continue-on-error` 的绕过配置。扫描报告应包含文件、行号、规则类型和结果指纹，但不得输出完整密钥。

### 4. 误报与例外审批

例外清单建议存放在受保护目录，例如：

```yaml
exceptions:
  - id: EXC-2026-0012
    fingerprint: sha256:...
    path: tests/fixtures/sample.env
    reason: "厂商文档示例，值已确认不可用"
    owner: team-security
    approver: security@example.com
    approved_at: 2026-08-16
    expires_at: 2026-11-16
    scope: "仅限该文件中的该检测结果"
```

审批流程：

1. 提交人提供检测指纹、位置、用途和是否可被外部访问；
2. 服务负责人确认内容不是有效凭据；
3. 安全团队或指定审批人批准；
4. CI 校验指纹、路径、分支范围和有效期；
5. 到期前自动提醒，逾期自动使 CI 失败。

禁止在例外中保存明文密钥、完整扫描输出或永久忽略规则。测试样例应优先替换为明显无效的占位符，减少例外数量。

### 5. 真实密钥处置与轮换

一旦确认真实凭据：

1. 立即阻断合并和发布；
2. 记录暴露位置、时间、仓库和可能访问范围；
3. 立刻吊销或禁用旧凭据；
4. 创建最小权限的新凭据，并通过密钥管理系统注入；
5. 检查访问日志，确认是否被使用；
6. 从当前代码、分支、构建产物和可访问历史中移除；
7. 必要时重写 Git 历史并清理缓存、镜像和制品；
8. 关闭事件前完成复扫并保留审计记录。

轮换不能替代吊销。已提交到远程仓库的凭据即使后来删除，也应按已暴露处理。

### 6. 测试方案

应覆盖以下测试：

- 有效云密钥、数据库密码和私钥能被识别；
- 同一密钥经过编码、拆分或不同文件格式仍能识别；
- 明确无效的测试占位符不会误报；
- 已批准且未过期的例外可通过；
- 例外指纹、路径或内容变化后重新失败；
- 例外过期、审批人缺失、格式错误时 CI 失败；
- 未批准真实凭据使 PR、主分支和发布流水线失败；
- 扫描器异常、网络失败或规则下载失败时 CI 失败；
- 扫描报告不会泄露完整密钥；
- 容器镜像和构建产物中的密钥同样会被拦截。

在 CI 中加入一组专用的“故意泄露但不可用”测试样例，验证失败路径；这些样例必须使用明确无效值，并隔离在安全测试目录中，避免被误认为真实事件。
