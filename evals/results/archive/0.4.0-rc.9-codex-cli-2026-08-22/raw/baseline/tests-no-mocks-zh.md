**支付重试服务测试方案**

### 1. 测试环境与原则

- 使用支付网关的 **sandbox 环境**，或启动一个真实的本地 HTTP 网关模拟进程；不使用 Mockito、stub、mock server 等 mock 技术。
- 数据库、消息队列、缓存使用独立的测试实例，优先采用 Testcontainers。
- 通过测试配置注入：
  - 最大重试次数
  - 初始退避时间
  - 最大退避时间
  - jitter 范围
  - 请求超时时间
- 时间验证使用可控的测试时钟或调度器；不在测试中真实等待完整退避周期。
- 每个测试使用独立商户、订单号和幂等键，测试结束后清理数据。

### 2. 核心测试场景

| 类别 | 场景 | 预期结果 |
|---|---|---|
| 成功 | 首次支付成功 | 返回成功；只产生一笔支付；状态变为 `SUCCESS`；不创建重试任务 |
| 成功 | 第 N 次重试成功 | 前 N-1 次失败，第 N 次成功；最终只有一笔成功支付；记录完整尝试历史 |
| 瞬时失败 | 网关返回 500/502/503 | 按策略重试；未超过最大次数时订单保持 `RETRYING` |
| 瞬时失败 | 网关返回 429 | 读取 `Retry-After`（如有）；按服务规则延迟后重试 |
| 瞬时失败 | 连接超时 | 视为可重试错误；不会因客户端超时而重复扣款 |
| 瞬时失败 | 网关连接中断但实际已扣款 | 查询支付状态或使用幂等键确认结果，不能再次扣款 |
| 永久失败 | 卡号被拒、余额不足等业务拒绝 | 不重试；状态变为 `FAILED`；记录明确失败原因 |
| 永久失败 | 参数校验错误、非法币种、签名错误 | 不重试；立即返回可诊断错误 |
| 永久失败 | 网关返回明确不可重试的 4xx | 不重试；告警或进入人工处理队列 |
| 重试上限 | 连续瞬时失败直到达到上限 | 恰好执行配置次数；状态变为 `FAILED` 或 `EXHAUSTED`；不再产生任务 |
| 恢复 | 服务在退避期间重启 | 重启后从持久化任务恢复，不丢失、不重复执行 |
| 恢复 | 消费重试任务过程中进程崩溃 | 任务根据租约/可见性超时重新投递，最终只形成一个支付结果 |

### 3. 退避策略验证

假设退避公式为：

```text
delay(n) = min(maxDelay, initialDelay × 2^(n-1)) + jitter
```

验证以下内容：

1. 第 1、2、3 次重试的基础延迟分别符合指数增长。
2. 延迟不会超过 `maxDelay`。
3. jitter 始终落在配置范围内。
4. 同一批任务不会全部在同一时刻重试，避免惊群。
5. 网关提供 `Retry-After` 时，优先级符合产品约定。
6. 达到最大重试次数后不再调度新任务。
7. 服务重启后，已计算的下一次执行时间保持一致，不重新从零开始计算。
8. 使用测试时钟推进时间，断言任务在“未到期时不执行、到期后只执行一次”。

### 4. 幂等性测试

#### 重复请求

- 同一 `idempotency_key`、同一请求体重复提交。
- 预期返回相同业务结果，不新增支付记录，不重复调用扣款接口。

#### 并发请求

- 多个真实客户端线程同时提交相同幂等键。
- 预期只有一个请求获得处理权，其余请求读取同一最终结果或进入等待状态。
- 数据库中只能存在一条支付主记录。

#### 键复用冲突

- 同一幂等键提交不同金额、币种或订单号。
- 预期拒绝请求，并返回幂等键参数冲突错误。

#### 重试幂等性

- 第一次请求网关超时，但网关实际成功。
- 重试时携带相同幂等键。
- 预期网关返回原交易结果，不产生第二笔扣款。

#### 结果持久化

- 支付成功后，在响应返回前终止服务。
- 客户端再次使用同一幂等键查询或提交。
- 预期返回已持久化的成功结果。

### 5. 测试数据与网关行为

本地真实网关进程或 sandbox 应支持通过测试订单属性触发确定性结果，例如：

- `success`
- `transient_3_times_then_success`
- `always_503`
- `declined`
- `timeout_after_charge`
- `rate_limited_with_retry_after`

这些是可部署的测试服务行为，不是进程内 mock；应通过 HTTP、数据库和消息队列真实交互。

### 6. 断言重点

每个场景至少检查：

- 最终支付状态
- 实际扣款次数
- 重试次数及尝试时间
- 下一次执行时间
- 幂等键记录
- 网关请求中的幂等键
- 数据库事务一致性
- 消息确认、重投递和死信状态
- 日志、指标和告警中的错误分类

### 7. 自动化分层

- **集成测试**：真实数据库、队列、网关进程，覆盖主要成功和失败路径。
- **端到端测试**：从客户端请求到最终支付结果，覆盖重启、超时和消息重投递。
- **并发测试**：验证幂等锁、唯一约束和竞态条件。
- **故障测试**：在网关调用前后、事务提交前后、消息确认前注入进程终止。
- **长时间稳定性测试**：大量订单混合成功、瞬时失败和永久失败，验证退避、吞吐和无重复扣款。

通过网关 sandbox、真实基础设施和可控测试时钟，可以在不使用 mock 的前提下稳定验证支付重试服务的业务正确性与可靠性。
